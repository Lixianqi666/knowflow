# ADR-002: 检索融合策略 — RRF vs 加权分数

**状态**：已采纳
**日期**：2026-05

## 背景

KnowFlow 采用双路检索——pgvector 向量检索 + BM25 全文检索。两路结果需要融合为一个排序列表。融合策略直接影响检索质量。

## 候选方案

| 方案 | 公式 | 特点 |
|------|------|------|
| **RRF (Reciprocal Rank Fusion)** | `score = Σ 1/(k + rank_i)` | 只用排名，无参数 |
| 加权分数 | `score = w1*vec_score + w2*bm25_score` | 用分数，需调权重 |
| 归一化加权 | `score = w1*normalize(vec) + w2*normalize(bm25)` | 归一化后加权 |
| 学习排序 (LTR) | ML 模型预测相关性 | 需训练数据和特征工程 |

## 对比分析

### 1. 分数量纲问题

- **向量分数**：cosine 相似度，范围 0-1
- **BM25 分数**：ts_rank，范围 0 到无穷大

直接加权 `0.5*vec + 0.5*bm25` 毫无意义——BM25 的高分会被成倍放大，淹没向量分数。必须先归一化。

### 2. 归一化的陷阱

| 归一化方法 | 问题 |
|-----------|------|
| Min-Max | 受离群值影响大，不同 query 的分数分布不同 |
| Z-score | 假设正态分布，但 ts_rank 偏态严重 |
| Softmax | 温度参数难调，放大了微小差异 |

归一化方法的选择本身就是一个新的调参问题。

### 3. RRF 的优势

RRF 完全绕过分数，只用排名：

```python
# rank 从 0 开始
score[chunk] += 1.0 / (k + rank + 1)
```

- **无量纲问题**：不管分数是 0.8 还是 8000，只看它排第几。
- **无需归一化**：省掉了一整个调参环节。
- **无监督**：不需要训练数据。
- **k=60 是论文推荐值**：来自 Cormack et al. 2009，在 TREC 实验中表现稳定。

### 4. RRF 的劣势

- **不利用分数信息**：排名第 1 和第 2 的差距，和第 100 和第 101 的差距一样大。实际上第 1 和第 2 的分数差可能很大。
- **冷启动问题**：某一路完全没有结果时，RRF 退化为另一路的排名。

### 5. LTR 的考量

学习排序理论上最优，但：
- 需要标注数据（query → 期望排序），企业知识库初期没有
- 特征工程复杂（分数、排名、文档元数据、用户行为）
- 模型训练和部署增加系统复杂度

对于当前阶段，LTR 的 ROI 不高。

## 决策

**采用 RRF，k=60。**

## 后果

### 正面

- 零调参，两路结果直接按排名融合。
- 实现简单（15 行代码），可维护性高。
- 对异常分数鲁棒——某一路分数异常不会影响融合结果。

### 负面

- 不利用分数差异，理论上不如 LTR 精准。
- 当两路结果完全不重叠时，RRF 退化为简单的交替排序。

### 优化方向

当积累足够用户反馈数据（thumbs up/down）后，可以：
1. 用反馈数据训练 LTR 模型，替换 RRF。
2. 或用反馈数据调 RRF 的 k 值（虽然论文推荐 60，但不同领域最优 k 不同）。

当前阶段的优先级是"能跑通且效果不差"，RRF 完美满足。
